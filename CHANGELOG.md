# Changelog

## Unreleased

- Backend: players push their work with `POST /api/submissions`: the changed focus files and a commit message, stored as the task's next attempt (V10). The push moves the task to `SUBMITTED`, and `PATCH /api/tasks/{id}/status` no longer can. `GET /api/submissions/latest` returns the active task's last push (P4-02).
- Backend: every seed task now targets `shopfront` and names the files the player edits (P4-01). Seven tasks are rewritten, and the three existing ones list only the files they change, including their test files. `shopfront` gains an `order/` area, a shipping calculator, a legacy sales report, four test files and a 400 response for `IllegalArgumentException`.
- Docs: plan Phase 4 in `docs/tasks/phase-4/` (P4-01 to P4-05) and update its `ROADMAP.md` tasks with the owner's decisions: the player edits the task's focus files, the seed tasks move onto `shopfront`, and the diff uses Monaco's diff editor.
- Docs: mark Design Stage 4 and the design roadmap as implemented, and record in `ROADMAP.md` that the Phase 4 design gate is met.
- Fix: closing a panel no longer leaves a large blue rectangle around the room object that opened it. Focus still returns there, but room hotspots now show focus only with their orange glow, because the default outline boxed the whole slanted object.
- Frontend: Login and the onboarding wizard now match Figma, with the room art on Login and new `StepperStep` and `Chip` components (`Chip` replaces `TopicChip`). `SelectionCard` gains the Figma types. The wizard locks Java, Spring Boot and Junior as the only MVP options and shows Mid and Senior as coming soon. Focus moves to the heading of each new step, so keyboard users don't lose their place.
- Frontend: the App Bar from Figma replaces the room's top strip, with a breadcrumb, the streak and "LV X" next to the real XP. Profile is now its own page at `/profile`, and `/room/profile` redirects to it. A shared layout around the room and Profile keeps open tabs across a Profile visit. The avatar opens a small menu with the email, Profile and Log out.
- Backend: `GET /api/progress` returns a mock `level` of `"X"` until the level model exists.
- Frontend: Task Board and Codebase now share one tabbed panel window from Figma, with a URL per tab and "Back to room". Tabs start from where they were left, including the open file, open folders and scroll position, after a tab switch or closing the panel. `Overlay` is now only for full-screen moments. Fix: `useSessionFlow` no longer repeats `GET /api/profile` on every route change.
- Frontend: add the `Button`, `Icon`, `Difficulty` and `StatusBadge` primitives from Figma and use them everywhere they apply, replacing the copied button class strings and `difficultyClasses()`. The Task Board header now shows difficulty and status on a row above the title. Disabled buttons use the design's 40% opacity.
- Frontend: apply the Night Shift foundation. Colours, radius and shadows now match Figma, including the missing tokens (`border-input`, `accent-ink`, the `*-subtle` set). Text on solid accent uses `accent-ink`, because the new orange fails contrast with light text. One global `:focus-visible` ring replaces the per-component `focus:` classes. Pixelify Sans, Space Grotesk and JetBrains Mono are self-hosted, and the 13 Figma text styles are available as classes. Monaco uses the Night Shift colours and Code/M type.
- Design: the Input component's Default border in Figma now uses a new `border/input` token (`night/500`, `#6C6494`), which reaches the Design Spec's 3:1 rule on both the surface (3.4:1) and the input fill (3.1:1). `docs/design/DESIGN_SPEC.md` is updated to match. The code still needs the token.
- Docs: record the owner's answers to design decisions D1–D11. Panel tabs now start from where they were left, kept alive with React's `<Activity>`. `AGENTS.md` notes that the plans in `docs/design` are the task spec for design work.
- Docs: update the Night Shift design plans after review. Phase 4 now waits only for Stage 1, `Button`, `Icon` and `PanelWindow`, and `ROADMAP.md` records that gate. The App Bar and standalone Profile get their own card, `Chip` moves to Stage 4, and `Input` moves to Phase 4. Button lists become searches, which adds the missed `CallbackPage` button.
- Docs: add `docs/design/DESIGN_SPEC.md`, a copy of the Figma Design Spec page, so the spec is readable from a clone without Figma access. Figma stays the source of truth. Link it from `README.md` and `frontend/SPEC.md`.
- CI: Jenkins Validate now runs the frontend build, so a compile error fails it, the same as GitHub Actions.
- Frontend tooling: oxlint is now the only linter. Remove ESLint, `typescript-eslint`, their plugins and `eslint.config.js`, which CI never ran. GitHub Actions and Jenkins now run `npm run format:check` (Prettier), and `src` is formatted to pass it.
- Frontend dependencies: update the minor-and-patch group, including `@auth0/auth0-react` 2.30. Auth0 now types the token as possibly `undefined`, so `fetchWithAuth` throws a 401 `ApiError` instead of sending `Bearer undefined`.
- CI: the backend job writes test totals, failed tests and per-package JaCoCo coverage to the GitHub Actions job summary, including when the build fails.
- Cleanup: remove `.kiro/` and the unused `quarkus-smallrye-jwt` dependency (`quarkus-oidc` provides `JsonWebToken`). Upgrade GitHub Actions to their Node 24 releases (`checkout` v7, `setup-node` v7, `setup-java` v6) and remove a stale H2 comment from `ci.yml`.
- Docs: add the Night Shift design implementation roadmap and its four stage plans in `docs/design/`.
- Frontend dependencies: update `vitest` and `@vitest/coverage-v8` to 5.1.0. Dependabot now groups them, because they must share a version.
- Frontend tests: add Vitest and React Testing Library with first tests for `lib`, hooks, components and pages, plus `npm test` and `npm run test:coverage` (at least 70% on logic). Coverage runs in GitHub Actions and the Jenkins Validate stage. Known bugs are recorded as `it.fails` tests linked to their cards.
- Security: `PATCH /api/tasks/{id}/status` now checks task ownership (another player's task returns 404) and only accepts player transitions, so players can't approve their own work (422). Verdicts and XP go through `TaskService.applyReviewVerdict`, which the Phase 5 review engine will call. Until then nothing can approve a task on a running server.

New tests cover the task state machine, the 500 fallback, unreadable codebase files and `UserService`. Overall: 100% lines, 95.8% branches (`dev` reported 93.2% / 73.2%). By package (lines/branches): codebase 100/87.5, exception 100/100, health 100/n-a, profile 100/100, progress 100/88.9, task 100/100, task.seed 100/100, topic 100/100, user 100/n-a.

Add `ProfileServiceTest` unit tests with Mockito.
- Fix: parallel `GET /api/tasks/today` or `POST /api/tasks/generate` calls could create several active tasks for one player. Creation now locks the player's profile row. Flyway `V9` removes existing duplicates, keeping the newest, and adds a partial unique index.
- Backend tests: run on Dev Services PostgreSQL 16 with the real Flyway migrations instead of H2 with `drop-and-create`, and remove `quarkus-jdbc-h2`. Docker is now required to run them. `SchemaValidationTest` boots with `generation=validate` to catch entity/migration drift, and tests use the V5 topic seed instead of re-inserting topics.
