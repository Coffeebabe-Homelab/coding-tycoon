# P2.1-03 — Frontend Production Container

**Phase:** 2.1 — Staging Deploy Slice
**Status:** 🔲 Not started
**Depends on:** P2.1-01

---

## Goal

Package the React/Vite frontend as a static production container suitable for staging.

---

## Acceptance Criteria

- [ ] Frontend has a production Dockerfile
- [ ] Docker build runs `npm ci` and `npm run build`
- [ ] Built assets are served by a minimal static web server
- [ ] SPA routing falls back to `index.html`
- [ ] Staging Auth0 and API settings are supplied through build args or documented runtime config
- [ ] Container exposes a single HTTP port for the staging reverse proxy
- [ ] `docker compose build frontend` succeeds from a clean checkout

---

## Implementation Notes

- Vite environment variables are normally build-time values; choose that path unless runtime config is explicitly needed.
- Keep the first staging version simple. A reverse proxy can be added later if HTTPS termination is handled outside Compose.
- Do not put Auth0 secrets in the frontend image. SPA client ID and audience are identifiers, not secrets, but still keep them environment-driven.

---

## Definition of Done

The frontend container serves the built app and can reach the staged backend API URL configured for the deployment.
