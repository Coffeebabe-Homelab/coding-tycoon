# P2.1-04 — Staging Docs and Smoke Checks

**Phase:** 2.1 — Staging Deploy Slice
**Status:** 🔲 Not started
**Depends on:** P2.1-01 through P2.1-03

---

## Goal

Document the staging deployment contract and add a minimal smoke-check flow that matches the existing Jenkinsfile.

---

## Acceptance Criteria

- [ ] Add a committed staging env example with placeholders only
- [ ] Document required Jenkins assumptions: `staging` branch, SSH alias, deploy path, Docker Compose availability, and credentials IDs
- [ ] Document Auth0 staging callback, logout, and web origin values
- [ ] Document first deploy and redeploy commands
- [ ] Document rollback steps using git revision plus Compose rebuild
- [ ] Add smoke-check commands for frontend availability, backend health, and container status
- [ ] Update README or deployment docs with the staging deploy path

---

## Implementation Notes

- The existing Jenkinsfile uses `docker compose -f docker-compose.yml build` and deploys the repo to `DEPLOY_PATH`.
- Keep the smoke checks shell-only so they can run locally or from Jenkins.
- Do not require an authenticated browser E2E test in this phase; document a manual authenticated task-board check.

---

## Definition of Done

A fresh staging host can be prepared and verified using only the documented environment file, Jenkins configuration, and smoke-check steps.
