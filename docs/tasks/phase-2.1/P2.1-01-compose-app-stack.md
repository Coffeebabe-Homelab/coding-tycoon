# P2.1-01 — Docker Compose App Stack

**Phase:** 2.1 — Staging Deploy Slice
**Status:** ✅ Complete
**Depends on:** P2-06

---

## Goal

Update the root `docker-compose.yml` so staging can build and run a minimal app stack: frontend, backend, and PostgreSQL.

---

## Acceptance Criteria

- [x] `docker-compose.yml` has `frontend`, `backend`, and `postgres` services
- [x] `backend` builds the Quarkus JVM app and exposes port `8080` inside the Compose network
- [x] `frontend` builds the Vite app and serves static assets over HTTP
- [x] `backend` depends on healthy `postgres`
- [x] PostgreSQL data persists in a named volume
- [x] Services use restart policies suitable for staging
- [x] Ollama is optional and not required for the staging deploy path
- [x] `docker compose up -d --build` starts the full minimal app stack

---

## Implementation Notes

- Keep a single root Compose file compatible with the existing Jenkinsfile.
- Prefer environment variables over hardcoded staging values.
- The backend should use `postgres` as the database hostname inside Compose.
- Do not commit real secrets.

---

## Definition of Done

Compose can build and start the minimal staging app stack from a clean checkout.
