# P2.1-02 — Backend Staging Configuration

**Phase:** 2.1 — Staging Deploy Slice
**Status:** 🔲 Not started
**Depends on:** P2.1-01

---

## Goal

Make the backend production profile deployable in staging through environment variables only.

---

## Acceptance Criteria

- [ ] Backend database URL, username, and password are read from environment variables
- [ ] Backend Auth0 domain and audience are read from environment variables
- [ ] CORS allowed origins can be configured for the staging frontend URL
- [ ] Backend binds to `0.0.0.0` in the container
- [ ] Flyway migrations run at startup in staging
- [ ] Health endpoint is available for deployment verification
- [ ] Missing required staging configuration fails fast with clear startup errors

---

## Implementation Notes

- Keep local development behavior unchanged.
- Use Quarkus `%prod` configuration for container/staging behavior.
- Document all required variables in the staging env example from P2.1-04.

---

## Definition of Done

The backend container starts in prod mode, connects to Compose PostgreSQL, applies migrations, and reports healthy.
